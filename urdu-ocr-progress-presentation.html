The Challenge That Taught Me the Most

Finding that 58% of my dataset was silently disappearing — with zero errors, zero warnings — was the moment this stopped feeling like a class assignment and started feeling like real engineering. No stack trace pointed at it. I only found it by comparing row counts against file counts and refusing to trust that "no error" meant "working correctly."

How I solved it

Traced the path-joining logic by hand, found two incompatible naming conventions from two different weeks of data collection, and wrote a resolver that tries both.

What it taught me

Silent failures are more dangerous than loud ones. Now I check row counts against file counts as a reflex, not an afterthought.

One Month at Code Saviours

🌱 What I learned

Tokenizer/decoder pretraining limits, exposure bias in seq2seq generation, why training loss and generation quality aren't the same thing, and how to debug a data pipeline systematically instead of guessing.

💬 Overall experience

Genuinely hands-on — real bugs, real dead ends, real research, not a scripted tutorial. Being told "0% accuracy is fine if you can explain why" changed how I approached the whole project.

🙏

Grateful for a mentor who cared more about how I debugged than what number I could show — that's the difference between finishing an assignment and actually learning research.
