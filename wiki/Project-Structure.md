## Week 1: Data Collection & Exploration

### `SI26-Week1/SI26_Week1_humna.ipynb`

**Purpose:** Initial exploration and data preparation

**Key Sections:**
- Data loading and EDA (Exploratory Data Analysis)
- Nastaliq font rendering and visualization
- Image classification by source (books, newspaper, synthetic, other)
- Label file creation and validation
- Utility functions for later use

**Inputs:**
- Raw images from `data/raw/` subdirectories
- Metadata about each image source

**Outputs:**
- `labels.csv` — Ground truth mapping

### `SI26-Week1/data/raw/`

Raw, unprocessed images collected from various sources:

| Directory | Count | Description |
|-----------|-------|-------------|
| `books/` | ~50 | Scanned or photographed Urdu text from books |
| `newspaper/` | ~50 | Images from Urdu newspapers (varying quality, ink, paper) |
| `synthetic/` | ~20 | Generated using `NotoNastaliqUrdu-Regular.ttf` font |
| `other/` | ~33 | Mixed sources, edge cases, miscellaneous |

**Total:** 153 images

### `SI26-Week1/data/labels.csv`

Ground truth file mapping images to their Urdu text content.

**Format:**
```
image_path,urdu_text,script_type
raw/books/book_001.png,"یہ اردو کا متن ہے",printed
raw/newspaper/newspaper_001.png,"خبر کی سرخی",printed
```

**Columns:**
- `image_path` — Path relative to data directory
- `urdu_text` — Ground truth Urdu script
- `script_type` — Source classification (printed, handwritten, synthetic, etc.)

### `SI26-Week1/NotoNastaliqUrdu-Regular.ttf`

A TrueType font file supporting Nastaliq script. Used for:
- Rendering synthetic training images
- Font visualization in notebooks
- Testing OCR on known text with consistent font rendering

## Week 2: Image Processing & Gap Analysis

### `SI26-Week2/SI26-Week2-Humna.ipynb`

**Purpose:** Preprocessing pipeline development and baseline OCR testing

**Key Sections:**
- Load raw images from Week 1 dataset
- Image preprocessing pipeline:
  - Grayscale conversion
  - Noise removal
  - Adaptive thresholding (Otsu's method)
  - Aspect-ratio-preserving resize
  - Binarization and output
- Tesseract baseline testing on 5 preprocessed images
- Gap analysis: comparing expected vs. actual OCR output
- Failure mode analysis

**Inputs:**
- Raw images from `../SI26-Week1/data/raw/`
- Labels from `../SI26-Week1/data/labels.csv`

**Outputs:**
- Processed images saved to `data/processed/`
- OCR results and error analysis
- Gap findings and recommendations

### `SI26-Week2/README_gap_analysis_section.md`

**Purpose:** Detailed documentation of preprocessing and Tesseract evaluation

**Contents:**
- Preprocessing algorithm explanation
- Evolution of preprocessing (3 rounds of iteration)
- Visual examples: raw vs. processed images
- Tesseract results table with error analysis
- Root cause analysis of failures
- Recommendations for custom model development

### `SI26-Week2/data/processed/`

Output directory for preprocessed images.

**Generated By:** Notebook preprocessing pipeline

**Purpose:** Store OCR-ready binary images for model training

**File Format:** PNG with 8-bit grayscale or binary (black/white only)

## File Naming Conventions

### Raw Images

Naming pattern: `{source}_{number}.png`

Examples:
- `book_001.png` — First book image
- `newspaper_050.png` — 50th newspaper image
- `synthetic_020.png` — 20th synthetic image

### Processed Images

Same base name as raw image, located in `data/processed/`:
- Input: `SI26-Week1/data/raw/books/book_001.png`
- Output: `SI26-Week2/data/processed/book_001.png`
